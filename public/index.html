INF653 States API

Use /states endpoints to query state data.

How to test this API (per project requirements)

1) API base URL

Root page: /
API root: /states/

2) Required GET routes

  • GET /states/ - all states with merged funfacts
  • GET /states/?contig=true - contiguous only (not AK, HI)
  • GET /states/?contig=false - non-contiguous only (AK, HI)
  • GET /states/ks - full state object for Kansas
  • GET /states/ks/funfact - random fun fact
  • GET /states/ks/capital - state + capital
  • GET /states/ks/nickname - state + nickname
  • GET /states/ks/population - state + formatted population
  • GET /states/ks/admission - state + admission date

3) Required funfact write routes

Set Content-Type: application/json for these requests.

POST /states/ks/funfact

{
  "funfacts": ["Test fact 1", "Test fact 2"]
}

PATCH /states/ks/funfact (index is 1-based)

{
  "index": 1,
  "funfact": "Updated fact"
}

DELETE /states/ks/funfact (index is 1-based)

{
  "index": 1
}

4) Required error checks

  • GET /states/kansas - should return invalid state abbreviation message
  • GET /states/al/funfact - should return no fun facts found message
  • POST/PATCH/DELETE with missing required body properties should return validation messages
  • PATCH/DELETE with out-of-range index (example: 99) should return index error

5) Catch-all 404 test

Request any invalid route like /not-a-route. For JSON clients, response should be { "error": "404 Not Found" }.

6) Final submission check

Run the automated tester against your deployed URL, fix failures, then submit your score.
